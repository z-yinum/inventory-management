Request Data Flow

User Interaction

2

Filter State

useFilters.getCurrentFilters() returns {warehouse, category, status, month}

3

API Call

api.js builds query string and fires Axios GET request to FastAPI

4

Backend Filter

apply_filters() + filter_by_month() run AND logic over in-memory data

5

Pydantic

Filtered list validated against typed model before serialization

6

Render

Vue computed properties derive display data; reactive DOM updates

Global Filter System

Time Period
?month=
  • Direct: 2025-01 … 2025-12
  • Quarter: Q1-2025 … Q4-2025
  • Omit for all periods
  • Not used by Inventory
Warehouse
?warehouse=
  • San Francisco
  • London
  • Tokyo
  • Omit for all locations
Category
?category=
  • Circuit Boards
  • Sensors
  • Actuators
  • Controllers · Power Supplies
Order Status
?status=
  • Delivered
  • Shipped
  • Processing
  • Backordered
Logic: All active filters are applied with AND logic. The string "all" is treated as "no filter" — omitted from the query string by api.js. Filters are stored as global Vue refs in useFilters.js (composable singleton) and apply to all views simultaneously. Quarter mapping: Q1 = Jan–Mar · Q2 = Apr–Jun · Q3 = Jul–Sep · Q4 = Oct–Dec.

API Endpoints

Inventory
GET /api/inventory List all stock items warehouse, category
GET /api/inventory/{item_id} Single inventory item (404 if not found) —
Orders
GET /api/orders List orders with full filtering warehouse, category, status, month
GET /api/orders/{order_id} Single order detail —
Dashboard
GET /api/dashboard/summary KPI summary — inventory value, low stock, pending orders warehouse, category, status, month
Demand & Backlog
GET /api/demand 9-item demand forecast with trend directions —
GET /api/backlog Unfulfilled orders — quantity gaps & delay days —
Spending
GET /api/spending/summary Totals: procurement, operational, labor, overhead + YoY % —
GET /api/spending/monthly 12-month spending breakdown by cost type —
GET /api/spending/categories Spending by category with % share and change —
GET /api/spending/transactions 200+ individual transaction records —
Reports
GET /api/reports/quarterly Q1–Q4 performance: revenue, fulfillment rate, avg order value —
GET /api/reports/monthly-trends Month-over-month order count, revenue, delivery trends —
Tasks (stub)
GET /api/tasks List user tasks —
POST /api/tasks Create task body: {title, priority, dueDate}
DELETE /api/tasks/{id} Delete task —
PATCH /api/tasks/{id} Toggle task completion —
Purchase Orders (stub)
POST /api/purchase-orders Create purchase order from backlog item body: PurchaseOrder
GET /api/purchase-orders/{backlog_item_id} Get PO by linked backlog item —

Data Files — server/data/

inventory.json
390+ items
  • 5 categories: Circuit Boards, Sensors, Actuators, Controllers, Power Supplies
  • 3 warehouses: San Francisco, London, Tokyo
  • Fields: sku, name, quantity_on_hand, reorder_point, unit_cost, location
  • Low stock: quantity_on_hand < reorder_point
orders.json
4,000+ orders
  • Date range: Jan–Dec 2025
  • Statuses: Delivered, Shipped, Processing, Backordered
  • Fields: order_number, customer, items[], status, warehouse, order_date, total_value
  • Revenue goals: $800K/month · $9.6M YTD
spending.json
Nested structure
  • spending_summary: total costs + YoY % change per type
  • monthly_spending: 12 months × 4 cost types
  • category_spending: Raw Materials, Components, Equipment, Consumables
  • Total ~$18.1M across all cost types
demand_forecasts.json
9 items
  • Trend directions: increasing, decreasing, stable
  • Fields: item_sku, current_demand, forecasted_demand, period
  • No filter support — always returns all 9
transactions.json
200+ records
  • Types: Purchase, Operational
  • Date range: Sept 2025
  • Fields: id, date, description, category, warehouse, amount, vendor, type
backlog_items.json
4 items
  • Priority levels: high, medium, low
  • Fields: order_id, item_sku, quantity_needed, quantity_available, days_delayed
  • Links to orders via order_id
